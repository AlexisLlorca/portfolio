La Decisión de Arquitectura: Modularizar
Extracción a src/components/ProjectCard.tsx

Decidimos extraer cada tarjeta de proyecto a su propio componente independiente. ¿Por qué es crucial para ti como futuro desarrollador?

🛡️ Principio SOLID y Mantenimiento Seguro
  • Single Responsibility: App.tsx solo debe encargarse de la estructura y maquetación de la página, NO de cómo se abre o cierra una tarjeta concreta.
  • Estado Aislado: Si una tarjeta tiene un botón para desplegar detalles (showDetails), solo ESA tarjeta debe tener memoria y cambiar. Las demás no se enteran ni consumen ciclos de cálculo.
  • Reutilización: Mañana puedes usar <ProjectCard /> en otra vista, en un modal o en una página de detalle sin duplicar código.

El contrato de Props: En Java declaras public void dibujar(Project p). En React declaras esta interfaz para exigir que quien use <ProjectCard /> le pase obligatoriamente un objeto de tipo Project.

Definición de la función componente. La sintaxis { project } se llama destructuring (desestructuración): saca la propiedad project del objeto de props recibido directamente.

Línea 10 const [showDetails, setShowDetails] = useState<boolean>(false);

showDetails es el valor actual (empieza en false, oculto).
setShowDetails es la función que React te da para modificar ese valor. Al llamarla, React redibuja la tarjeta en pantalla de forma automática.

Líneas 12-14 const toggleDetails = () => { setShowDetails(!showDetails); };

Función manejadora del clic (event handler). Invierte el booleano: si era falso pasa a verdadero, y si era verdadero pasa a falso.

Línea 17 <div className="flex flex-col justify-between p-6 rounded-2xl bg-slate-900/40 border border-slate-800 hover:border-slate-700 transition-all hover:-translate-y-1 group">

Clases de Tailwind explicadas:
• flex flex-col justify-between: Coloca los hijos en columna vertical y empuja el pie de tarjeta hacia el fondo.
• p-6 rounded-2xl: Padding interno de 24px y bordes muy redondeados.
• bg-slate-900/40: Fondo azul oscuro translúcido (40% de opacidad).
• hover:-translate-y-1: Efecto flotante al pasar el ratón (sube 4 píxeles).
• group: Permite que los elementos interiores reaccionen cuando pasas el ratón por cualquier parte de la tarjeta.

Líneas 37-47 <button onClick={toggleDetails}> ... </button>

Al hacer clic ejecuta toggleDetails.
Usa un operador ternario (showDetails ? ... : ...) para alternar el texto del botón y cambiar el icono entre ChevronUp y ChevronDown.

Líneas 50-67 {showDetails && ( <div ...> ... </div> )}

Renderizado Condicional de Cortocircuito: En JavaScript, true && elemento devuelve el elemento; false && elemento no pinta nada. Es el equivalente exacto a un bloque if en Java para mostrar u ocultar la caja de arquitectura.

Líneas 70-81 {project.tags.map((tag, idx) => ( <span key={idx}>{tag}</span> ))}

Depuración y Errores Reales: Casos Prácticos
Lo que aprendimos resolviendo los problemas de hoy

Durante la sesión encontramos 4 situaciones técnicas habituales en el desarrollo profesional:

1. Error: verbatimModuleSyntax y 'import type'

El error: TS1484: 'Project' is a type and must be imported using a type-only import.

Por qué ocurre: Vite y TypeScript moderno tienen activada la regla verbatimModuleSyntax. Si importas una interfaz como si fuera un objeto de Javascript ordinario (import { Project }), el empaquetador no sabe si tiene código que ejecutar o no. Solución: usar siempre import type { Project } para contratos e interfaces.

2. Error: Case Sensitivity en librerías (ChevronUP vs ChevronUp)

El error: TS2724: '"lucide-react"' has no exported member named 'ChevronUP'. Did you mean 'ChevronUp'?

Por qué ocurre: En TypeScript y JavaScript los nombres son estrictos con mayúsculas y minúsculas (case-sensitive). La librería exporta ChevronUp (con 'p' minúscula). Al poner la 'P' mayúscula, el import devolvía undefined.

3. Error: ProyectCardProps vs ProjectCardProps (Typo en el contrato)

El error: TS2552: Cannot find name 'ProjectCardProps'. Did you mean 'ProyectCardProps'?

Por qué ocurre: En español escribimos "Proyecto" con 'y', pero en código estándar en inglés usamos "Project" con 'j'. Al definir interface Proyect... pero tipar ({ project }: ProjectCardProps) con 'j', TypeScript avisaba de que eran nombres distintos.

4. Entorno: Restricted Mode y Format on Save en VS Code

La situación: Al abrir VS Code en Linux, aparecía la barra azul de Restricted Mode y al buscar format on save ponía "No matching results".

La solución:

  • El buscador Ctrl + P busca archivos del proyecto. Para abrir la Configuración de VS Code hay que pulsar Ctrl + , (Control + Coma).
  • En Restricted Mode, VS Code desactiva extensiones y formateadores por seguridad. Al pulsar "Trust folder" se desbloquean todas las herramientas de desarrollo.
5. Error de Sintaxis: Código huérfano tras refactorizar (Todo en rojo)

El problema: Al pegar el nuevo <ProjectCard />, el código antiguo de 45 líneas se quedó por debajo sin borrar.

Por qué se marca todo en rojo: El código antiguo contenía variables como project.category y etiquetas </div> fuera del bucle .map(). Al no tener el contexto ni las etiquetas de apertura, el compilador JSX de TypeScript rompe el árbol de elementos visuales. La solución fue limpiar ese bloque sobrante.

Feedback Visual y Asincronía: Botón Copiar Correo
Uso de navigator.clipboard y setTimeout

Implementamos un botón en la sección de contacto que copia el email real al portapapeles del sistema operativo y ofrece retroalimentación visual inmediata.

☕ Equivalencia con Java / DAM

En Java Desktop accederías al Toolkit.getDefaultToolkit().getSystemClipboard() y necesitarías un Timer o un hilo Thread.sleep() para resetear la interfaz. En React usamos las APIs asíncronas del navegador junto con el Hook useState.

src/App.tsx Lógica del Portapapeles 
const [copiedEmail, setCopiedEmail] = useState<boolean>(false);

const handleCopyEmail = () => {
  navigator.clipboard.writeText(personalData.links.email);
  setCopiedEmail(true); // Cambia el estado a copiado (botón verde con check)
  setTimeout(() => {
    setCopiedEmail(false); // Tras 2000 ms (2 segundos), vuelve al estado normal
  }, 2000);
};
1. API Clipboard navigator.clipboard.writeText(...)

Función asíncrona estándar de los navegadores modernos para escribir texto en el portapapeles del usuario con seguridad.

2. Temporizador setTimeout(() => { setCopiedEmail(false); }, 2000);

Programa la ejecución del reseteo para que la confirmación visual dure exactamente 2 segundos en pantalla.

3. Clases Dinámicas copiedEmail ? 'bg-emerald-500/20 border-emerald-500...' : 'bg-slate-900...'

En Tailwind usamos plantillas literales con operador ternario para cambiar el estilo visual según el valor de copiedEmail.

El Flujo Mental de Git: Del Escritorio al Álbum
Working Directory, Staging Area, Commits y Navegación

Comprender Git es indispensable en DAM. No se trata de memorizar comandos, sino de entender las 3 zonas de trabajo:

📸 La Analogía de la Foto Oficial
  • 1. Working Directory (Tu Escritorio): Los archivos que editas en VS Code. git status los muestra en rojo.
  • 2. Staging Area (El Escenario): Con git add . subes los cambios al escenario para prepararlos. git status los muestra en verde.
  • 3. Repositorio Local (La Foto / Commit): Con git commit -m "..." disparas la cámara y la foto queda guardada en el historial permanente (consultable con git log).
⚠️ Error Típico: "fatal: no es un repositorio git"

Por qué ocurre: Ejecutas comandos de Git estando en tu carpeta personal (~) en lugar de estar dentro de la carpeta del proyecto.

Solución: Navegar con cd ~/Repositorio-Git/portfolio antes de lanzar comandos Git, o usar la terminal integrada de VS Code que se abre directamente en la raíz del proyecto.

La Mini-Terminal Linux Interactiva
Security by Design, Hooks useRef / useEffect y Scroll Interno Aislado

Creamos un componente autónomo (src/components/InteractiveTerminal.tsx) que simula una terminal Linux para que cualquier reclutador o visitante pueda interactuar con comandos como whoami, skills, projects o sudo hire.

🛡️ Análisis de Seguridad (Security by Design)
  • Inmunidad a Command Injection: No hay backend ni ejecución de procesos en el servidor. Opera como una máquina de estados determinista mediante un switch con Allowlisting estricto.
  • Inmunidad a XSS: React escapa por defecto todos los valores de las cadenas renderizadas en el Virtual DOM (trato de texto plano tipo textContent, sin dangerouslySetInnerHTML).
  • Sandbox del Navegador: Aislamiento total en el cliente sin acceso a ficheros locales ni variables de entorno sensibles.
1. Hook useRef const terminalBodyRef = useRef<HTMLDivElement>(null);

Permite referenciar el contenedor interno de la terminal y enfocar el cursor sin manipular el DOM de forma descontrolada.

2. Hook useEffect (Scroll Interno) terminalBodyRef.current.scrollTop = terminalBodyRef.current.scrollHeight;

Efecto reactivo que desplaza únicamente el interior de la ventana de la terminal al escribir, sin mover la página web principal.

Autoevaluación Táctil (Flashcards para el móvil)
Toca cada tarjeta para comprobar si dominas el concepto
❓ 1. ¿Qué hace `useState` y por qué no usamos una variable normal? 👆 Toca
En React, modificar una variable normal (let x = 5) no le avisa al motor que debe volver a pintar la pantalla. useState proporciona una función set... que le indica a React: "este valor ha cambiado, redibuja el componente ahora mismo".
❓ 2. ¿Qué es el "destructuring" `{ project }` en los parámetros de la función? 👆 Toca
React siempre pasa un único objeto llamado props con todas las propiedades juntas (ej. props.project). Usar { project } extrae esa propiedad directamente para que puedas usarla como una variable limpia sin escribir props. todo el tiempo.
❓ 3. ¿Para qué sirve el atributo `key={project.id}` en el bucle `.map()`? 👆 Toca
Es el equivalente a la clave primaria (PRIMARY KEY) en SQL. Permite al algoritmo de reconciliación de React rastrear exactamente qué tarjeta cambió, se añadió o se eliminó en el DOM sin tener que destruir y reconstruir todas las demás tarjetas de la página.
❓ 4. ¿Por qué usamos `import type` en TypeScript moderno? 👆 Toca
Porque con la regla verbatimModuleSyntax, TypeScript garantiza que los tipos e interfaces que solo existen en tiempo de diseño no dejen rastro de código ni pesen en el archivo JavaScript final que se descarga el usuario en su navegador.
