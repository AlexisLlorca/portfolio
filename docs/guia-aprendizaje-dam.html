Mapa de Arquitectura y Conexiones del Proyecto
Cómo viajan los datos y cómo colaboran los archivos

Una aplicación moderna en React + TypeScript no es un único bloque monolítico, sino una red modular de piezas conectadas. Aquí puedes ver el flujo exacto:

1. Capa de Datos src/data/portfolioData.ts define las interfaces (tipos) y almacena los datos reales (nombre, biografía, proyectos, formación).
⬇️ import { personalData, type Project }
2. Orquestador Central src/App.tsx recibe los datos, estructura la página (Hero, Seguridad, Formación, Contacto) y coordina los componentes hijos.
⬇️ Pasa props y renderiza componentes
3. Componentes Especializados • ProjectCard.tsx recibe un proyecto y gestiona su estado desplegable.
• InteractiveTerminal.tsx ejecuta comandos simulados con allowlist seguro y scroll aislado.
⬇️ npm run build & git push origin master
4. Despliegue CI/CD deploy.yml en GitHub Actions toma el resultado compilado en dist/ y lo publica en vivo en GitHub Pages.

En React, los datos siempre viajan en una sola dirección: de padres a hijos (flujo unidireccional). Las props son parámetros inmutables que un componente recibe para renderizarse.

☕ Equivalencia con Java / DAM

Pasar una prop es idéntico a llamar a un constructor o método pasándole un parámetro por valor: new TarjetaProyecto(proyecto). El componente hijo no puede modificar el objeto original del padre; solo puede leerlo.

La Mini-Terminal Linux Interactiva
Security by Design, Hooks useRef / useEffect y Scroll Interno Aislado
🔗 Conexión de este paso en el proyecto:
Origen Entrada de texto del usuario o botones rápidos de comandos (whoami, skills, sudo hire).
➔
Este paso procesa Valida el comando en un switch con Allowlist (inmune a inyección) y añade la respuesta al historial.
➔
Destino Desplaza con scrollTop exclusivamente el interior de la terminal sin mover la ventana web.
🛡️ Análisis de Seguridad (Security by Design)
  • Inmunidad a Command Injection: No hay backend ni ejecución de subprocesos en la máquina. Opera como máquina de estados con Allowlisting estricto.
  • Inmunidad a XSS: React escapa por defecto todos los valores de las cadenas renderizadas en el Virtual DOM (trato de texto plano, sin dangerouslySetInnerHTML).
  • Scroll Aislado: Usamos terminalBodyRef.current.scrollTop = terminalBodyRef.current.scrollHeight para desplazar únicamente el interior de la consola, evitando los saltos bruscos de scrollIntoView().

// 1. Importa los hooks necesarios: estado, referencias al DOM y sincronización reactiva
import { useState, useRef, useEffect } from "react";
// 2. Iconos vectoriales temáticos para la ventana
import { Terminal, CornerDownLeft, Trash2 } from "lucide-react";

// 3. Estructura que tipa cada línea almacenada en la terminal
interface TerminalEntry {
  command: string;           // Comando escrito por el usuario
  output: string | string[]; // Respuesta (cadena simple o array de líneas)
  isError?: boolean;         // Si es true, el texto se pinta en tono rojizo
}

export function InteractiveTerminal() {
  // 4. Estado reactivo para el input de texto que escribe el usuario
  const [input, setInput] = useState<string>("");
  // 5. Historial de comandos ejecutados en la sesión
  const [history, setHistory] = useState<TerminalEntry[]>([
    {
      command: "welcome",
      output: [
        "👋 ¡Bienvenido a la terminal interactiva de Alexis Llorca!",
        "💡 Escribe 'help' o pulsa en los comandos rápidos para interactuar.",
      ],
    },
  ]);

  // 6. Referencias a elementos del DOM sin provocar re-renderizados innecesarios
  const terminalBodyRef = useRef<HTMLDivElement>(null); // Caja con scroll de la terminal
  const inputRef = useRef<HTMLInputElement>(null);       // Campo de texto del prompt

  // 7. useEffect reactivo: cada vez que el historial cambia, hace scroll interno
  useEffect(() => {
    if (terminalBodyRef.current) {
      // 8. CRUCIAL: Modifica solo el contenedor interno, sin mover la página del navegador
      terminalBodyRef.current.scrollTop = terminalBodyRef.current.scrollHeight;
    }
  }, [history]); // Se ejecuta cuando cambia 'history'

  // 9. Lógica de comandos seguros con ALLOWLIST (Inmunidad contra inyección de comandos)
  const handleCommand = (cmdText: string) => {
    const trimmed = cmdText.trim().toLowerCase();
    if (!trimmed) return;

    if (trimmed === "clear") {
      setHistory([]);
      setInput("");
      return;
    }

    let output: string | string[] = "";
    let isError = false;

    // 10. Switch con allowlist cerrada: cualquier comando no listado va al caso por defecto
    switch (trimmed) {
      case "help":
        output = [
          "📋 Comandos disponibles:",
          "  👤 whoami       - Información sobre mi perfil y titulación",
          "  ⚡ skills       - Stack tecnológico y herramientas principales",
          "  🚀 projects     - Resumen de mis proyectos destacados",
          "  📬 contact      - Canales de contacto directo",
          "  🔑 sudo hire    - Comando especial para ofertas y reclutadores",
          "  🧹 clear        - Limpiar la pantalla de la terminal",
        ];
        break;
      case "whoami":
        output = [
          "👤 Nombre: Alexis Emmanuel Llorca",
          "🎓 Titulación: 2º de DAM | Máster en Ciberseguridad",
          "🛡️ Filosofía: 'Security by Design' — software robusto desde el código.",
        ];
        break;
      case "skills":
        output = [
          "💻 Lenguajes: Java, Kotlin, TypeScript, JavaScript, SQL, Python",
          "🛡️ Ciberseguridad: OWASP Top 10, Hardening, Criptografía",
          "🐧 Sistemas & DevOps: Linux, Docker, Git/GitHub, Bash",
        ];
        break;
      case "sudo hire":
        output = [
          "🔐 [PRIVILEGIOS CONCEDIDOS]: root@alexis",
          "✨ ¡Alexis está listo para incorporarse a proyectos y prácticas de DAM!",
        ];
        break;
      default:
        // 11. Manejo seguro de entradas desconocidas
        output = `❌ Comando no encontrado: '${trimmed}'. Escribe 'help' para ver los comandos válidos.`;
        isError = true;
    }

    // 12. Actualiza el historial de manera inmutable agregando la nueva entrada
    setHistory((prev) => [...prev, { command: cmdText, output, isError }]);
    setInput("");
  };

Autoevaluación Táctil (Flashcards para el móvil)
Toca cada tarjeta para comprobar si dominas el concepto
❓ 1. ¿Qué hace `useState` y por qué no usamos una variable normal? 👆 Toca
En React, modificar una variable normal (let x = 5) no le avisa al motor que debe volver a pintar la pantalla. useState proporciona una función set... que le indica a React: "este valor ha cambiado, redibuja el componente ahora mismo".
❓ 2. ¿Qué es el "destructuring" `{ project }` en los parámetros de la función? 👆 Toca
React siempre pasa un único objeto llamado props con todas las propiedades juntas (ej. props.project). Usar { project } extrae esa propiedad directamente para que puedas usarla como una variable limpia sin escribir props. todo el tiempo.
❓ 3. ¿Para qué sirve el atributo `key={project.id}` en el bucle `.map()`? 👆 Toca
Es el equivalente a la clave primaria (PRIMARY KEY) en bases de datos relacionales. Permite al algoritmo de reconciliación de React rastrear exactamente qué tarjeta cambió o se eliminó en el DOM sin tener que destruir y reconstruir todas las demás tarjetas de la página.
❓ 4. ¿Por qué usamos `import type` en TypeScript moderno? 👆 Toca
Porque con la regla verbatimModuleSyntax, TypeScript garantiza que los tipos e interfaces que solo existen en tiempo de diseño no dejen rastro de código ni pesen en el archivo JavaScript final que se descarga el usuario en su navegador.
❓ 5. ¿Por qué usamos scrollTop en vez de scrollIntoView en la terminal? 👆 Toca
scrollIntoView() desplaza toda la ventana del navegador provocando que la página web salte bruscamente hacia abajo. Asignar terminalBodyRef.current.scrollTop = terminalBodyRef.current.scrollHeight desplaza exclusivamente el interior de la caja de la terminal sin mover la página.
